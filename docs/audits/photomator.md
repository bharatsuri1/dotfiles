# Photomator

## Role

Apple-native photo editor for Photos-library and file-based nondestructive work.

## Recommendation

Retain provisionally as the preferred lightweight editor; compare directly with Darkroom before declaring both baseline.

## Modern baseline

Choose Photos-browser versus file-browser ownership per library, use nondestructive edits/sidecars where portability matters, and keep originals independently backed up. Avoid automatic ML edits as an unreviewed ingest default.

## Host and legacy audit

Photomator is installed with its sandboxed application identity. No tracked configuration exists.

## Configuration ownership

Bootstrap via supported distribution. Photos data, edits, sidecars tied to private images, presets, account state, and caches remain local/private. Only intentionally exported personally-authored presets are candidates for a separate assets backup.

## Integration notes

Overlaps strongly with Darkroom and partly Capture One/ON1. Vesper must not tint color-critical surfaces.

## Open decisions

- Choose Photomator versus Darkroom for quick edits and define when work graduates to Capture One.
